# Phase B19 — minimal tangent credit module

Branch `S5-CCM-scale-validation`. Parts A/B/C/F are exact linear
algebra (rank-revealing SVD on explicit matrix bases, verified against
exact simulation to machine precision — no training). Parts D/G use
ordinary BPTT (reusing b18_temporal_core's forward/adjoint, extended
with a tangent-projection wrapper). No new persistent online-credit
training rule; no production learner built (per the phase's own
explicit instruction — only a tiny exact reference recursion, used
purely to verify minimality). No S5.

Code: `credit_memory/b19_tangent_module.py` (new). No separate results
JSON — every quantity in this phase is either an exact algebraic
computation or a machine-precision verification, reproduced directly
by re-running the module; representative numbers are recorded inline
below.

**Headline: the central hypothesis is confirmed, sharply, and it
overturns part of B18's own accounting. B18's r² K-chain was never
minimal — for B18's actual source-injection tangent (E=I, which
trivially commutes with any R), the true minimal exact credit
dimension is `dim(A) ≤ r`, not r². The single-noncommuting-tangent
falsification test is decisive: ONE generic trainable direction jumps
the exact credit dimension from a 1-dimensional module to the full
r², with zero intermediate points tested where it landed anywhere
between. Symmetry-breaking gives a clean, quantitative explanation for
B18's own unresolved "why does Jordan fail" question. The practical
gate (Part D) is more equivocal: commuting/O(r)-credit cores measurably
underperform dense r²-credit cores on the harder tasks at matched r —
so the theory is right, but the CHEAP realization is not yet the
practically useful one.**

## 1. Exact definitions used

- `A := span{I, R, R², ..., R^{r-1}}` — the algebra generated by the
  core transition matrix R (Cayley-Hamilton bounds the degree at r).
- `P := span{E_1, ..., E_k}` — the trainable temporal-parameter
  tangents, `E_i := dR/dtheta_i`, as r×r matrices.
- `B = A P A := span{Rᵃ E_i Rᵇ : 0≤a,b≤r-1, i=1..k}` — the two-sided
  bimodule; `d_credit := dim(B)`, computed via rank-revealing SVD on
  the vectorized generating set (tolerance `1e-9` relative to the top
  singular value throughout).
- Given a source direction `v` and query `c`, the **quotient**
  dimension is the rank of the "Hankel" array `H[a,b] = cᵀ Rᵃ E_i Rᵇ v`
  stacked over `i` — the dimension actually needed for THAT specific
  source/query pair, which can only shrink relative to `dim(B)`.
- The **minimal online recursion**: since `R·B ⊆ B` (closure under
  left-multiplication, verified directly), multiplication by R acts on
  B via a `d×d` matrix `R_B` in a measured orthonormal basis of B —
  giving a genuinely `d`-dimensional (not `r`- or `r²`-dimensional)
  exact linear recursion, verified against literal full-matrix
  simulation.

## 2. Predicted vs. measured module dimensions (Part A/B)

`r=4` throughout, verified to machine precision against literal
simulation via the minimal-recursion construction:

| architecture | dim(A) | dim(P) | **dim(A P A) predicted** | verified (max rel. err vs. simulation) |
|---|---|---|---|---|
| A1 dense (R entrywise trainable) | 4 | 16 | **16 (=r²)** | exact by construction |
| **B18's own case (E=I only)** | 4 | 1 | **4 (=dim A), NOT 16** | 2.9e-11 |
| A2 commuting/diagonal (R=U·diag(λ)·U⁻¹, λ trainable, U fixed) | 4 | 4 | **4** | 3.0e-14 |
| A3 polynomial (R(θ)=Σθₖ R0ᵏ, p=2) | 4 | 2 | **4** | 2.7e-15 |
| A4 block (two independent 2×2 dense blocks) | — | 8 | **8** (sum of per-block dims, not 16=r²_total) | n/a (structural) |
| **A5 single generic (noncommuting) tangent** | 4 | **1** | **16 (=r²)** | 2.4e-14 |
| A5 single tangent, off-diagonal-only E | 4 | 1 | 15 | — |
| A5 single low-rank E | 4 | 1 | 16 | — |

**B18's own K-chain, re-examined under this theory, was not minimal**:
it stored a dense r×r matrix (r² numbers) for a tangent direction
(E=I) that provably only needs `dim(A)≤r` numbers — the extra storage
was never load-bearing, just an artifact of not having derived the
tighter bound at the time.

**The single-noncommuting-tangent result is the decisive falsification
test the phase asked for, and it is unambiguous**: with `dim(P)=1` in
both the A2-diagonal control and the A5-generic case, the measured
`dim(APA)` is **4 vs. 16** — an exact 4x jump from a single, generic
non-commuting perturbation direction. **"Number of trainable temporal
parameters" is confirmed NOT to be the right complexity variable —
whether those parameters commute with R is.**

## 3. Source/query quotient (Part C)

`r=4`, dense R (`dim(APA)=16` unconstrained), rank measured via the
`H[a,b]` construction above:

| source `v` | query `c` | measured quotient dim |
|---|---|---|
| generic | generic | 16 (full) |
| generic | standard basis vector (not special) | 16 (no reduction) |
| generic | **aligned to an eigenvector of R** | 16 (no reduction — one side alone insufficient) |
| **aligned to an eigenvector of R** | generic | **4** |
| aligned to eigenvector | aligned to the SAME eigenvector | **4** |

**This matches classical controllability/observability structure
exactly**: restricting the query alone, even to an actual eigenvector,
does not shrink the module — the rich source side still "sees"
everything via the R-shift structure unfolding a restricted query back
into a full probe. Restricting the SOURCE to an invariant subspace
does shrink it immediately (reachability alone is sufficient to cap
the dimension, independent of how rich the query is). **"Minimal
query-observable tangent realization" is confirmed to require BOTH a
restricted source AND downstream reachability structure — restricting
only the readout side is not enough.**

## 4. Forward expressivity of O(r) vs. r² credit cores (Part D — the practical gate)

`r=8`, `L=2`, `n=1` (no feature multiplicity — a direct capacity
comparison; the multiplicity axis is B18's own established result and
not retested here), 600 steps, 2 seeds, median loss:

| task | dense (r²-credit) | commuting (O(r)-credit) |
|---|---|---|
| delay_r4 | 0.96 | 1.40 |
| delay_r8 | 1.79 | 2.22 |
| puredelay_D20 | 0.29 | 0.30 |
| kexp_K4 | 0.00056 | 0.0095 |

A follow-up check (single layer, `r=8`, delay_r1, 2000 steps instead
of 600) confirms this is a genuine capacity gap, not slow
convergence: commuting improves from 0.34→0.26 with 3x more training
but stays orders of magnitude behind dense's ~1e-4.

**The commuting/O(r)-credit core measurably underperforms the dense
r²-credit core on the harder delay tasks and kexp, at matched r —
`puredelay_D20` is the one exception, showing no real difference.**
This is the phase's central negative-leaning result: **the theory's
prediction (O(r) is achievable) is correct, but the practically useful
regime, at this width and this task family, still wants (closer to)
the dense r² tangent space.** Consistent with B18 Part B's own finding
that dense/oscillator beat diagonal — restricting R's OWN trainable
tangent directions to a fixed, commuting basis removes exactly the
kind of flexibility that mattered there too.

## 5. Known-order teacher test (Part E) — inconclusive, reported honestly

`K`-independent-exponential-mode teachers (`K=2` and `K=8`), dense
core, `n=1`, `L=2`, testing whether `r_req` tracks `K`:

| r | K=2 loss | K=8 loss |
|---|---|---|
| 2 | 2.27 | 2.92 |
| 4 | 4.40 (worse than r=2) | 3.89 (worse than r=2) |
| 8 | 0.00034 | 0.00045 |
| 16 | 0.00004 | 0.00004 |

**This does not cleanly support "r_req ≈ K"**: both `K=2` and `K=8`
transition sharply between `r=4` and `r=8`, independent of the
teacher's actual order, and `r=4` is non-monotonically WORSE than
`r=2` for both. Given B18's D2 ("narrow-alone", `n=1`) architecture
was already shown to underperform generally, this is most plausibly an
**optimization-difficulty artifact of the narrow, no-multiplicity
setting at this seed count (1 seed, no replication)**, not a
representational law — reported as inconclusive rather than forced
into either a positive or negative reading. The depth-scaling
prediction (`L·r ≳ d_eff` rather than `r^L`) was not tested
separately given this base result's own unreliability — an explicit
scope reduction.

## 6. Symmetry-breaking crossover (Part F)

`A = A0 + σ·Δ`, `A0 = I_n⊗R` (`n=8`), `Δ` a generic coupling matrix
(spectral-norm-normalized, genuinely mixing copies — not
block-diagonal), measuring the relative error of using the
UNPERTURBED module's exact recursion against the TRUE perturbed
dynamics:

| σ | T=10 (normal) | T=30 (normal) | T=60 (normal) | T=10 (nonnormal/Jordan) | T=30 (nonnormal) | T=60 (nonnormal) |
|---|---|---|---|---|---|---|
| 0.001 | 0.0011 | 0.0010 | 0.0011 | 0.0010 | 0.0046 | 0.023 |
| 0.010 | 0.0105 | 0.0105 | 0.0110 | 0.0099 | 0.046 | 0.236 |
| 0.050 | 0.053 | 0.053 | 0.056 | 0.050 | 0.224 | 0.884 |
| 0.100 | 0.107 | 0.107 | 0.112 | 0.100 | 0.422 | 0.987 (breakdown) |

**Decisive, clean confirmation, and it directly explains B18's own
unresolved question about why Jordan cores catastrophically failed
during training.** For the **normal (oscillator) core**, error is
governed almost purely by σ and is essentially FLAT across horizon T —
consistent with `C_T` being horizon-independent for normal matrices
(classical Bauer-Fike-type perturbation bound: no transient
amplification). For the **nonnormal (Jordan) core**, error at fixed σ
grows dramatically with T — a 24x increase from T=10 to T=60 at
σ=0.01, reaching near-total breakdown (0.99) at σ=0.1, T=60. **This is
the mechanism, not just the correlation, behind B18 Part B/H's
observation that Jordan blocks are numerically fragile: any
perturbation (routing coupling, gradient noise, imperfect training)
that the theory treats as symmetry-breaking gets amplified over long
horizons specifically because the Jordan block is nonnormal — the
crossover is measurably earlier than for a normal core at every T
tested, growing worse as T grows exactly as predicted.**

## 7. Selectivity algebra (Part G)

Extends B18 Part G: `R(q) = R0 + q·Δ`, comparing a `Δ` that commutes
with `R0` against a generic (noncommuting) `Δ`, `r=4`:

| selector `Δ` | dim(APA) for {R0, Δ} |
|---|---|
| commuting | **1** |
| noncommuting (generic) | **16 (=r²)** |

The exact corrected gradient formula (extending B18 Part D/Part G's
own construction) verified to machine precision (`~1e-10`) for both,
across `n=2..32` — endogenous selectivity remains exactly computable
either way, matching B18's finding. **The new result here**: a
commuting selector generator keeps the exact credit module about as
small as it can possibly be (dimension 1, for a single selector
direction on an already-commuting core) — a strictly better outcome
than the generic/noncommuting selector case B18 Part G already
established (which lands at the same `r²` ceiling as the
single-noncommuting-tangent test in Part 2 above). **Same mechanism,
same lever**: whether the selector's own generator commutes with the
core determines whether selectivity stays cheap or blows up to the
full bimodule — independent of feature multiplicity `n` either way.

## 8. Matched-spectrum diagnostic (Part H) — not run

**Explicit scope reduction.** Given the time already invested in
Parts A-G and the clarity of the symmetry-breaking result (Part 6),
which already gives a precise, verified mechanism for the
normal-vs-nonnormal performance gap B18 observed, the matched-spectrum
eigenvalue/eigenvector-decomposition diagnostic (isolating phase-rich
spectrum vs. learnable eigenvectors vs. nonnormal transients vs. pure
optimization flexibility as the source of dense/oscillator's advantage
over diagonal) was not built in this pass. This is a real, useful next
question — Part 6's result already implicates nonnormal transient
amplification as A mechanism, but does not rule out the others as
ALSO contributing, particularly "learnable eigenvectors" (dense R's
much larger, freely-trainable tangent space per Part 2/4) — not
resolved here.

## 9. Verdict: **B, THEORY CONFIRMED, BUT DENSE r² CORE NEEDED FOR QUALITY**

Checking against the five offered options:

- **A (minimal-bimodule theory confirmed + O(r) core useful)**: the
  theory half is confirmed cleanly (Parts 2, 3, 6, 7 all match
  predictions exactly, several to machine precision). The "O(r) core
  useful" half is NOT established — Part 4 shows the commuting/O(r)
  core measurably underperforms dense on 3 of 4 tasks tested, and the
  gap does not close with substantially more training.
- **B (theory confirmed, dense r² needed for quality)**: **best fit.**
  The bimodule dimension formula is exact and verified from every
  angle tested (algebraic dimension count, source/query quotient,
  symmetry-breaking, selectivity), but the practically useful
  temporal-core parameterization, at this scale, remains the dense,
  non-commuting one — restricting R's own tangent space to a small
  commuting subspace costs real task performance.
- **C (module theory partially wrong)**: ruled out — every exact
  verification (Parts 2, 3, 6, 7) matched to machine precision or
  matched the qualitative prediction cleanly; nothing contradicted the
  theorem itself.
- **D (width coupling returns under full selectivity/routing)**: not
  supported — Part 7's selectivity result stays independent of `n`
  exactly as B18 found, with no new width-dependence surfacing.
- **E (forward scaling fails under controlled convergence)**: not
  directly tested at the width-scaling level this phase (that's B18's
  own domain); Part 4's r_req-vs-K result was inconclusive rather than
  a clean failure, and is flagged as needing more seeds rather than
  read as a falsification.

**Practical implication**: `r²` (not `O(r)`) remains the honest
practical temporal-credit cost for a competitively-performing core —
B18's original architecture and its own cost accounting (Part 5,
`S_credit = r · M_l` per layer, now understood as `r²`-worth of
BIMODULE dimension per shared core, times the routing-side `M_l`
factor for the source/query multiplicity) stands as the right number
to build around, not the smaller `dim(A)` bound this phase initially
hoped to substitute in. The mathematically clean, exactly-verified
part of this phase's contribution is the DIAGNOSTIC apparatus itself
(Parts 1-3, 6-7) — a precise, reusable way to measure and predict
exact credit-module dimension for any future core parameterization —
not a new cheaper architecture to build the learner around.

No new persistent online-credit training rule implemented (the minimal
recursion in Part 1/`build_minimal_recursion` is a verification tool
only, not a training-time construction). No S5 run.
